Basically a server is a powerful computer that serves information, files, or services to other computers. How a server works:
1. The request: You click a link, check your email, or open an application.
2. The delivery: Your device sends a digital request over the internet to the server.
3. The response: The server processes a request then it sends the response back to your device.


The commonly used servers are:
- web servers
- game servers
- file servers
- mail servers
- Database Server
- Caching Server

Why can't we use our laptop/low hoardware as a server?
1. Servers never sleep. They are designed to run 24 hours a day, 365 days a year without crashing.
2. They are built for huge traffic handling. A laptop can handle one user or ten users but a server handles thousands of users at the exact same time.

2. Reserved Instance : 
--> Commitment for 1yr / 3 yrs.. You get big discount in the pricing.
--> This is best for a steady predictable workload or an always-on kind of application. 

Reserved instances we have two options:
1. Standard reserved instance: This will be locked to a specific instance type or region with a good discount.
2. Convertible reserved instance: We can change the instance family/size at a slightly lower discount than a standard reserved instance but we have that flexibility to change the configuration.

Three pricing options in reserved instances:
1. Full upfront: pay 100% of the amount and you get your instance.
2. Partial upfront: pay 30-60% of the amount now then AWS will reduce the hourly price, you pay based on the reduced hourly price.
3. No upfront: pay everything on a usage basis.

** We can sell our reserved instances in AWS Marketplace, if we dont want it anymore.

An AWS key pair is a security credential mechanism used to authenticate your identity when connecting to an EC2 instance. It uses an asymmetric encryption method, meaning a public key and private key method.

An EBS snapshot is basically a point-in-time incremental "backup of an EBS (Amazon Elastic Block Store) volume". 

Can I see what files we have inside a snapshot? 
Answer:  NO. If you want to see the files, you create a volume attached to any of the instances, then only we can view the files. 


Q: we have an existing unencrypted EBS volume. How will you convert it to an encrypted one? 
Ans: we don't have a direct option to modify an EBS volume and enable encryption. There is no direct setting. We have a workaround:
1. We need to create a snapshot of an unencrypted EBS volume.
2. We can create a volume from the snapshot.
3. While we are creating the volume we do have an option to enable encryption.
4. Once we have created a volume with encryption enabled, we can attach this volume to an existing instance and we can detach the old one.
5. Once data verification, validation, and basic sanity checks are completed, we can delete the old unencrypted volume.

Q: we have an EC2 instance in AP South 1a. It has a volume with a lot of data. We need the entire data for another EC2 instance in another availability zone or the instance may be in another region. What is the process? 
Ans: as both EC2 instances are in different availability zones or different regions, we don't have a direct option to detach and attach. We cannot even use the copy volume option as they are in different regions.
1. We have to create a snapshot.
2. We have to create a volume from the snapshot.
3. If another instance is in the same region but another availability zone, we need to create the volume from the snapshot. If another instance is in another region, we need to copy the snapshot.
4. We need to create the volume.
5. We can attach it to the instance.

RTO : Recovery Time Objective : 
Question : How long we can be offline. / How much downtime offord.
Meaning: Downtime limit
Focus: Recovery speed
Example : if our RTO is 4 hours, we must have our systems up and running with in 4 hours. 


RPO : Recovery Point Objective : 
Question : How much data loss we can afford.?
Meaning: Data loss limit
Focus: Backup frequency
Example: If our RPO is set to 4 Hr, you must have backup configured for every 4 Hr.


DLM : Data Lifecycle Manager : 

We don't have any option to directly pick the volume or instance. We have to choose tags for filtering the resources. 

We do have an option to filter resources and create backups by using an instance-level tag or an individual volume-level tag. 


Q: explain your EC2 instances' backup strategy. 
Ans: we are using the AWS DLM (Data Lifecycle Manager) service to take backups of our EBS volumes. We are not using any third-party applications. We have a compliance standard: for every resource we create in EC2 we must add an environment tag. We are using that environment tag to filter the resources with DLM. For example whenever we are configuring it in the production environment as per our requirement, we have configured a backup frequency of every 4 hours. We also have a retention policy: we are retaining resources for 4 days in the production environment and 2 days in the non-production environment.
