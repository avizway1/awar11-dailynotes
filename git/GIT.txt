Git is a version control system. It's a tool that records snapshots of our project over time so we can review history, undo mistakes, and collaborate without overwriting each developer's work.

			  CVS - concurrent version system 		- x files, x dire, 1 user
			  
2000		- SVN - subversion						- x files, x dire, x users

2005		- GIT - Global Information Tracker		- branching, cherry pick

Generally the best method developers follow : 
- They always fetch and pull, first before they start their day 
- Before they are pushing their code to the remote repo. 


===================

clone : we can get a copy of our entire codebase to our local machine. 
- Whenever you get a new laptop you need to get the entire codebase to your new laptop. 
- Whenever any new team member joins, he needs to start work. 
- If it is a public repository you use the "HTTPS" method to clone. 

pull : when multiple team members are working on the same repository, if you want to get their changes to your local laptop, then you can run the `pull` command. 
- Before they start their day 
- Before they are pushing their code to the remote repo.
