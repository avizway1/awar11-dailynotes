Invocation models for Python:  (When code has to run)

Synchronous Invocation : The caller (LB, APIGateway, lambda function URL) sends the requests for response, lambda runs the function and return the result directly to the caller.

Asynchronous Invocation : The caller (SQS, SNS, EventBridge, S3) sends the request for response, Lambda return with status code (202), Then starts the process and sends the result to the caller. If the function fails, it sends the event to DLQ (Dead Letter Queue) and retries 2 times.. 

Event Source mapping : lambda polls the source for new records at service (SQS, MSK - kafka, DynamoDB) and invokes the lambda function when it finds the new records.. 


Eventbridge : We can invoke lambda funciton based on Schedule / Event.

lambda_Handler : This is the entry point to the lambda function. Execution starts here.

lambda function will have 3 Phases in its lifecycle

1. INIT Phase : Initialisation Phase : Download the code, Initialisae the runtime to run the code..
2. INVOKE Phase : Execute the handler function. The Active phase of lifecycle - CODE RUN, BUSINESS LOGIC RUN..
3. SHUTDOWN Phase : For a period of inactivity.. AWS Destroys the environment and free the resources.. 


Cold start : INIT + INVOKE : First invoke or invoke after a long period of inactivity, Lambda starts with latency/delays.

Warm start : INVOKE Phase only : Environment will be available to run the code, so we dont get high latency..

How to reduce cold start time in Lambda service.?
--> Provisioned cuncurrency
--> SnapStart

AWS SnapStart is a performance optimisation feature designed to reduse COLD START startup latency by upto 10 times.
