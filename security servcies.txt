

Cloudtrail : THis service contineously logs AWS account activities. 
--> Its enabled by default. it can store all logs for 90 days without any addl configuration.
--> We can send logs to s3 bucket, we do have option to send logs to cloudwatch and configure rentewntion perios using Life cycle rule. 
--> We can filter logs using multiple options i.e; username, accesskey, eventname, event source.. 

With CLoudtrail, We can only log AWS activities, We cannot track / log events occuring inside EC2 instances / S3 Object.. 

We have 4 types of trails:

1. Management Trail : Captures aws operations performed on AWS console 9Instance launch / s3 bucket create / iam user create / Delete)
2. Data Trail : S3, lambda, dynamodb : We can enable data trail for current and future s3 buckets also.. 
3. Insight Events : Helps to identify abnormal traffic, errors or user behaviour..
4. Network Trail : Network flow events.. 

AWS Organisations : We can bring multiple aws accounts under one roof.
We can enable logs at organisatins level. All account logs store in single s3 bucket.
When external auditor visits our org, Create an IAM user with s3 read and provide access on central logging bucket.

AM IAM users credentials got compromosed. How you troubleshoot.?

--> Disable the user, Reset the password, Enable MFA.
--> What are the activities the user performed using compromised cred. 
--> Did that user created any other users / changed any existing users password.
--> Inspect VPC flow logs, NACLs to Block traffic, Allow login only from trusted networks.
--> Incident Investigation / Remediation / RCA - Root Cause Analysis.
