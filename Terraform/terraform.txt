statefile : it contains information about the resource that we have in our cloud environment. 

terraform init			: Initialise our working directory by downloading the required provider plugin. 
terraform fmt			: Automatically formats code with proper indentation and spacing. 
terraform validate		: Checks .tf files for syntax errors. 
terraform plan			: Shows what Terraform will create, change, or delete. This is a dry run. Won't create a resource. 
terraform apply			: Create, update, or destroy the resources on the AWS environment. 
terraform destroy		: Destroys or deletes the resources. 

terraform apply -auto-approve : non-interactive way to apply resource.

Terraform meta-arguments are special configuration keys provided by the Terraform language itself rather than individual cloud providers.

1. count
2. for_each
3. depends_on
4. provider
5. lifecycle : Customizes how Terraform handles the execution workflow 
	5.1 create_before_destroy
	5.2 prevent_destroy
	5.3 ignore_changes
	5.4 replace_triggered_by


Parallelism in Terraform : by default Terraform can create, update, or destroy resources concurrently to maximise the deployment speed. It has a limit of 10 operations by default. 

terraform apply --parallelism=5

--------------------------------------------------------

In Terraform we do have an option to destroy only one particular resource from the entire template. We can use an argument called `target` to pick the specific resource. 


terraform state list				: Shows all the resources the current state file is monitoring or managing. 

1. aws_instance.mumbai-server
2. aws_s3_bucket.mybucket

terraform state show aws_instance.mumbai-server			: Displays only one particular resource block's information managed by the state file. 

terraform destroy -target=aws_instance.mumbai-server	: Delayed only one particular resource from the entire stack. 


terraform destroy -target=aws_instance.mumbai-server -target=aws_instance.mumbai-server-2
