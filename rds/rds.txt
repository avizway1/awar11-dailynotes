Single-AZ DB instance deployment (1 instance): Creates a single DB instance without standby instances. This setup provides:
99.5% uptime & No data redundancy

Multi-AZ DB instance deployment (2 instances): Creates a primary DB instance with a "non-readable standby instance" in a separate Availability Zone. This setup provides:
99.95% uptime & Redundancy across Availability Zones.

Multi-AZ DB cluster deployment (3 instances) : Creates a primary DB instance with "two readable standbys" in separate Availability Zones. This setup provides:
99.95% uptime & Redundancy across Availability Zones
Increased read capacity & Reduced write latency

A cache is a high-speed temporary data storage layer that holds frequently accessed data in memory. 
--> The primary goal of a cache is to serve future data requests faster. 
--> The cache will significantly reduce the workload on the primary database. 
--> very less latency
--> primary database load will decrease.

How cache works: 
1. Cache hit : the application checks the cache first. If the requested data is found it is returned instantly. 
2. Cache Miss : if data is not in the cache, the application is forced to query the primary database. Once it retrieves the requested information, data is sent back to the user and written or stored into the cache. The next time someone asks for the exact data, it results from cache. 

Common caching strategies: 
Cache-Aside : Cache-Aside is the most common approach. The application explicitly talks to both the cache and the database. The application checks the cache first. If it misses, it queries the database and manually updates the cache. 

Write-Through : the application writes data directly to the cache, which synchronously updates the backend database before completing the operation. 

write-behind (write-back): the application writes data straight to the cache, which immediately acknowledges the write. The cache then updates the primary database synchronously later.

Primary key : it's a unique column in a database table that guarantees every single row can be identified. 

Rules of Priamry key:
1. Uniqueness : No two rows in table can share same primary key

Redshift : redshift offers OLAP on AWS. It can integrate with other AWS services. It's called an AWS data warehousing solution. 

Leader Node : the leader node plans the query execution and it is responsible for executing the query and providing the result. 
Compute Node : a compute node is a machine that actually stores all the huge data. 

WLM : workload management : WLM helps us to control how queries can use cluster resources so one heavy query doesn't choke everything else. 

How WLM works: WLM lets you create queues. Each queue gets a dedicated slice of memory and concurrency slots. 

Queue : a lane of data flow
Each queue has a memory limit and max concurrency slots.
Queries routes to Queue based on rules.

Auto WLM : redshift automatically manages the memory and concurrency. 
Manual WLM : we can define the queue's memory percentage and slots ourselves.

DMS : Database Migration Service. We can use this DMS service to perform homogeneous migrations and heterogeneous migrations. 

homogeneous migrations : Same class of DB source and target data migration. (mysql --> mysql)
heterogeneous migrations : Diff class cource and target migration (Mongodb --> postgre)

Full Load : Replicate all existing data once.

CDC - Change Data Capture : Ongoing changes will replicate

Full Load + CDC : Once full load and then ongoing changes will replicate.
