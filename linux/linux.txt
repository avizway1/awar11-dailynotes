How OS boots:
1. Hardware Initialisation. 
	1.1  When we press the power button the motherboard's firmware, like BIOS or UEFI loads.
	1.2. It runs a POWER ON SELF TEST (POST) to check the crucial hardware like RAM, CPU, and storage. Uses primary boot device. 

2. Boot Sector: Firmware looks for execution instructions from the storage disc partition layout. 

--> Generally we will have something called the Master Boot Record (MBR) and 
--> In recent devices we are getting something called EFI or UEFI. It bypasses the entire MBR thing and reads execution files directly from storage partitions. 
--> This boot sector primarily finds and runs the primary boot loader. 

3. Bootloader (GRUB2)

--> Grand Unified Bootloader (GRUB) is the most common software responsible for loading our operating system. It displays a splash menu for users to select an operating system or kernel version if they have configured multiple operating systems. 

Otherwise it picks a default operating system and it loads. 
--> In the backend it loads the Linux kernel image from vmlinuz and the initial RAM file system (initramfs) into system memory. 

4. Lunux Kernel: 
--> It acts as a translation layer and bridge between user software applications and the physical computer hardware, like a CPU, memory, and devices. 

5. Initialisation System (systemd) : the kernel executes the initialisation daemon as the very first user-space process, granting it a process ID. Systemd acts as a master controller, reads the configuration target files, and spins up required processes concurrently.

Addl volume : apart from root all other volumes are considered additional volumes. We can use this to store the data. 

root volume : gp2, gp3, io1, io2, standard..
Addl volume : gp2, gp3, io1, io2, standard, sc1, st1

==========

gp2 and gp3 : general purpose SSD : we use these general-purpose volumes for common workloads. 

gp2 : Min 1 Gb, Max 16 TB.. 1 gb volume gives us 3 IOPS (1:3 ratio), with min of 100 IOPS.. - 16k IOPS
gp3 : Min 1 Gb, Max 64 TB.. Min 3000 IOPS and Max 80,000 IOPS - We have option to adjust IOPS based on our workload requirements, IOPS cost us.. 

--------

io1 and io2 : Provisioned IOPS : if our workload requires a specific IOPS count, then we can go with the provisioned IOPS option. It costs a bit more compared to all other models but it is the one that gives the best performance among all. 

io1 : min 4 Gb, Max 16 TB.. 1 gb gives 50 IOPS by default
io2 : Min 4 gb, max 64 TB.. Min 100 IOPS, Max 200000 IOPS

-------

HDD : sc1, st1 : These are HDD volumes, lower performance compared to SSD, but very cheap.. 

st1 / Throughput optimsied HDD : suitable for bigdata, datawarehousing and log processing kind of workload..
sc1 / cold hdd : same use case as st1, but lower cost with lower performance.. 

Min: 125 GB.. Max: 16 TB.. 

-------

Standard / magnetic : Low cost storage solution.. Min 1 GB.. Max 1 TB..

step 1 : Create a volume in same AZ as our ec2 instance and attach the volume. 

Identify the volume name: lsblk -pf
New volume path: /dev/nvme1n1

step 2 : Verify the new volume has any file system

sudo file -s /dev/nvme1n1

output: data		: No file system

step 3 : Write a file system to the new volume

sudo mkfs -t xfs /dev/nvme1n1

sudo file -s /dev/nvme1n1
lsblk -pf


step 4 : mount the volume to directory

cd /mnt/
sudo mkdir nowvol

sudo mount /dev/nvme1n1 /mnt/nowvol

----

step 5 : make the mount persistent, that can survive reboot / stop and start of ec2 instance..

cat /etc/mtab | grep nvme1n1

/dev/nvme1n1 /mnt/nowvol xfs rw,seclabel,relatime,inode64,logbufs=8,logbsize=32k,sunit=8,swidth=8,noquota 0 0

write above entry into /etc/fstab file

sudo vim /etc/fstab

save and quit

mount -a
mount -all

To increase existing volume size
1. We first have to increase the volume size in the AWS console.
2. We need to perform operations at the OS level.

sudo xfs_growfs -d /mnt/nowvol

-----

To increase the root volume size:
1. We first have to increase the volume size in the AWS console.
2. Root volume mounted to a partition so we need to use the `growpart` command.

sudo growpart /dev/nvme0n1 1

We need to reboot instance..
