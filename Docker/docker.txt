Microservices 

================================================


Physical Server : Hardware, Network, OS, librariers, Runtime, Application / Code..
Security, Maintenance, cooling, Power COnnection/UPS, 
problem : 	Time, Money - Upfront, 
			Scaling - Vertical ( Adding more RAM / CPU on Same server) / Horizontal (Adding more servers).



Monolith : 
- Slow and Risky Releases - every change ships with every other change. 
- All - or - Nothing Scaling - scale the entire application. 
- One bug takes down everything - a memory leak in the cart module crashes payments and order services also. 
- Locked into one technology: you struck with one language and one framework for total application. 


Microservices : 
- Independent Deployment : Payments- Deployment
- Targeted Scaling : More load on payments- scale only payments
- Fault isolation : if the recommendation service fails, the customer can still browse and pay. 
- Right tool per job : python for ML, Go - apigw, Java - billing..
- Small, owning teams
- Easier to understand

Docker : Docker is an open platform for building, shipping, and running applications inside containers. 

Docker Engine : a background service that builds and runs containers.

Container : a running instance of an image. 
- We can take all our application code. 
- We can write instructions (Dockerfile).. 
- Then we can build Dockerfile. 
- We get an image. 
- Once you run that image you get the container. 

Dockerfile : a text file with steps to build an image.

Image : a read-only template containing the application and its dependencies 

Registry : a store for images, such as Docker Hub, ECR, or GHCR.


Step by step process: 

step 1 : Gather all the applicaiton code..

step 2 : write a dockerfile..

step 3 : Build the docker file, we get an image..

step 4 : we can push the image to Registry (Dockerhub / ECR - Elastic Contianer Registry / GHCR - GitHub Container Registry)

step 5 : We/anyone can pull the image and run it. Here we get a "Container"..

Passing environment variable to the container 

Option 1 : Command line (-e : stays in shell history)

docker run -d --name mysql -e MYSQL_ROOT_PASSWORD=s3cret1213 mysql:latest
	
option 2 : Pass env variables From a file (**Preferred method and never commit it to git)

docker run -d --name mysql2 --env-file ./myvars.txt mysql:latest


** When we run the `docker inspect` command, both options (option 1 and option 2) will display the environment variable and its values so we don't use this option for very sensitive information like passwords or API keys.
