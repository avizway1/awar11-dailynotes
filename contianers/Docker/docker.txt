Restart policies: A restart policy controls what happens when a container exists ot the host reboots.


no					: Never restart. THis is default option.
on-failure[:N]		: Restart only if the container exists with an error, optionally at most N times.
always				: Always restart, including after a host reboot.
unless-stopped		: like "always", except a container you stopped by hand stays stopped.


docker run -d --name mynginx1 --restart=always -p 8080:80 nginx:latest

docker run -d --name mynginx2 --restart=unless-stopped -p 8080:80 nginx:latest

Both are in running state.. and restarted..

docker stop mynginx1
docker stop mynginx2

										always							unless-stopped
										-----------						-----------------
Container crashed						restart automatically			restart automatically
Host rebooted - container running		restart automatically			restart automatically
Host rebooted - You stoped container	starts again					stays stopped

----

Bridge Mode: 
Will have its own IP address inside the Docker network 
-p parameter required for port mapping.
Traffic passes through NAT so one extra hop is added. 
More isolated containers won't expose unless we publish on a port. 
Best for normal and multi-container applications. 
Works on Linux, Mac, and Windows. 

Host Mode: 
It shares the host IP address and port. 
Port mapping not required. 
Less isolation: our container directly exposed over the host network 
Slightly faster as there is no NAT and one less hop.
We can use for monitoring, agent, and networking tools. 
Supports only Linux.

A Dockerfile is a recipe for an image. Each instruction adds a layer. 

-----

FROM 		: Set the base image. This must be the first instruction in the Dockerfile. 

FROM alpine
FROM ubuntu:latest
FROM python:3.13-alpine
FROM node:22
FROM amazonlinux
FROM redhat/ubi8:1221212 (universal base image)

---

RUN			: Execute a command while the image is being built. 

RUN dnf update -y && dnf install nginx -y && dnf clean all

** To follow best practise while writing your Dockerfile, reduce the layers. 
Chain commands with && to keep layers count few. 

---

WORKDIR		: Sets the work directory for all the subsequent commands we are going to execute. 

WORKDIR /app
WORKDIR /usr/share/nginx/html/
WORKDIR /var/www/html/

----

COPY		: It copies files from the build folder into the image.  

COPY . .
COPY src/ /app
COPY . /usr/share/nginx/html/

COPY <source-path> <container-path>

---

ADD			: Similar to `copy` but it also supports zip files. Generally we use `copy` most of the time. 

ADD mydata.tar.gz /app

---

CMD			: CMD sets the default command to run when a container starts. CMD will be overridden if we pass an argument while running the `docker run` command. 


CMD["nginx","-g","daemon off;"]

If we have multiple containers to deliver an application, running the `docker run` command for every container is difficult and hard to perform. 

Compose : it's a single YAML file that describes all containers of our application. One command can start them all. 


sudo mkdir -p /usr/libexec/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-$(uname -m) -o /usr/libexec/docker/cli-plugins/docker-compose
sudo chmod +x /usr/libexec/docker/cli-plugins/docker-compose
